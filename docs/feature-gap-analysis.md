# Feature gap: Interview Coach, public iQua, and target implementation

Baseline claims below are static observations of the repository's initial `HEAD`, primarily `InterviewPage.tsx`, `GroupDiscussionPage.tsx`, `naturalVoice.ts`, and server routes. Source presence does not establish that a production workflow succeeds. Reference observations are detailed in [reference-analysis.md](reference-analysis.md); advertised features remain distinguished from live behavior.

| Capability | Existing Interview Coach baseline | iQua public evidence | Target behavior | Required validation |
| --- | --- | --- | --- | --- |
| Landing and navigation | Existing product landing, sign-in, dashboard, and role-specific pages | Public hero, feature descriptions, institutional marketing, sign-in route; mobile landing overflow observed | Preserve product identity, keep useful working routes, and provide clear configuration/meeting entry points | Desktop/mobile actions, keyboard paths, meaningful loading and errors |
| Authentication and onboarding | MongoDB/session auth routes and existing profile structures | Sign-in and password-recovery input states observed; login/onboarding unavailable | Server-authenticated sessions, safe profile access, and accessible auth errors | Authorized login, failed credentials, ownership and role tests |

| Conversational interview | List-based question index and per-answer feedback; browser pause can automatically submit | Actual session and follow-up behavior unverified | Valid state transitions, one primary question, answer-grounded follow-ups, compact session memory, and explicit candidate submission | Multi-turn provider UI test with no repeated/stale question and evidence of context retention |
| Female speech | Groq Orpheus profiles already present, with local/device fallback, generation counters, and no explicit provider queue | Actual voice identity and quality unverified | Selectable Hannah/Autumn/Diana, stable identity, cancellable queue, preserved pitch, explicit provider/fallback choice, and visible failure recovery | Deterministic queue tests, native audio lifecycle checks, actual synthesis timings, human listening |

The voice work adds a provider abstraction, bounded cancellable queue, explicit fallback setting, microphone capture/VAD, and base64 JSON STT client while preserving existing endpoint contracts. Unit and synthetic native-browser checks cover implementation behavior; no Groq credentials or authorized reference account were supplied, so actual Orpheus quality and complete spoken interview acceptance remain open.

Implementation status for the other parallel workstreams belongs in [verification-report.md](verification-report.md). This comparison does not label target capabilities as working merely because corresponding code exists.
